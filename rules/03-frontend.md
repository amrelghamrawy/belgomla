# 03 — Frontend (Next.js) Standard

The frontend counterpart of `01-testing.md` + `02-architecture.md`. Every UI session (Tasks 9, 10, …) follows it. When a situation is not covered, decide once, write it here, and follow it.

Product constraints it serves: **Arabic only, RTL-first, mobile-first** (01 §6, Tech §8). The storefront is designed for phones; the dashboard must work on phones but is optimised for tablet/desktop (tasks/10).

---

## 1. Stack (decided once)

| Concern        | Choice                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------- |
| Framework      | Next.js 16 App Router, React 19, TypeScript `strict` + `noUncheckedIndexedAccess`                |
| Styling        | Tailwind CSS v4 (PostCSS plugin), theme tokens in `app/globals.css` (`@theme inline`)           |
| Components     | shadcn/ui, `radix-nova` style, `rtl: true` in `components.json` (D38). Generated into `components/ui` |
| Server state   | TanStack Query. No other global store                                                           |
| Forms          | react-hook-form + zod (`@hookform/resolvers`), shadcn `Field` components for layout and errors  |
| API types      | `openapi-typescript` from `backend/openapi.json` → `lib/api/schema.d.ts` (generated, never edited) |
| Font           | IBM Plex Sans Arabic via `next/font/google` (D40)                                               |
| Unit tests     | Vitest + Testing Library + jsdom; `fetch` stubbed per test (`stubFetch` in `tests/unit/http.ts`) |
| E2E            | Playwright, `mobile` (390×844) and `desktop` projects                                            |
| Lint / format  | ESLint flat config (`eslint-config-next` core-web-vitals + typescript) + Prettier (+ tailwind plugin) |
| i18n           | None. Arabic copy lives in `lib/copy/ar.ts`                                                     |

Next.js 16 notes: `middleware.ts` is now `proxy.ts`; `next lint` is gone (`npm run lint` = `eslint .`); `cacheComponents` + `partialPrefetching` are on, so **every client component that reads `useSearchParams()` is wrapped in `<Suspense>`** (the build fails otherwise), and hidden routes keep their state (`<Activity>`), which is why logout does a full reload (`window.location.assign`). Before using a Next API you have not used in this repo, read its page in `node_modules/next/dist/docs/`.

Which file to write:

| You need…                                      | Write                                                     |
| ---------------------------------------------- | --------------------------------------------------------- |
| A call to a new endpoint                       | add it to `backend/openapi/openapi.yaml` → `php artisan api:openapi` → `npm run api:types`; then a hook in the surface's `lib/...` file using `apiFetch` |
| Read data for a screen                         | `useXQuery()` hook with a key from `lib/api/keys.ts`       |
| Change data                                    | `useXMutation()` hook that invalidates the affected keys   |
| A form                                         | zod schema next to the form mirroring the backend `rules()`, `useForm` + `zodResolver`, server `details` mapped to fields with `applyServerErrors()` |
| A piece of UI used by both surfaces            | `components/shared/`                                      |
| Any Arabic text                                | a key in `lib/copy/ar.ts`                                  |
| Money, dates, phones on screen                 | `lib/format/*`, never inline formatting                    |
| A list page that must paint fast (LCP)         | prefetch its first screen in the server page with `prefetchListing()` (`lib/server/store-data.ts`) into a `HydrationBoundary`, under the same query keys as the client hooks; give the query a `staleTime` so hydration does not refetch |
| State in the URL (filters, sort, search)       | parse/serialise in a pure `lib/store/*` module, `router.replace(..., { scroll: false })`; never local state. Dashboard lists use `useListQuery(keys)` (`lib/dashboard/use-list-query.ts`); changing a filter resets `page` |
| A dashboard page                               | `app/(dashboard)/dashboard/(shell)/<area>/page.tsx` rendering a component from `components/dashboard/<area>/`; the shell already guards the session, so pages never call `useRequiredDashboardUser()` themselves |
| A retry-safe write (D55)                       | `useIdempotencyKey(prefix)` (`lib/api/idempotency.ts`) and send `Idempotency-Key: keyFor(body)`; `reset()` on success |
| A list endpoint with extra top-level keys      | `apiFetchPage<T, Meta, { unread_count: number }>()` keeps them next to `data`/`meta` |
| A page that needs a logged-in customer         | `useRequiredCustomer()`: renders nothing until known, sends a guest to `/account/login?next=` |

## 3. RTL and mobile-first rules

- `<html lang="ar" dir="rtl">` once in the root layout; Radix gets `DirectionProvider dir="rtl"`.
- **Logical utilities only**: `ms-/me-/ps-/pe-`, `start-/end-`, `text-start/text-end`, `rounded-s/e`, `border-s/e`. Physical `ml-/mr-/pl-/pr-/left-/right-/text-left/text-right/rounded-l/r/border-l/r` are rejected by ESLint (`no-restricted-syntax` on class strings). The one exemption is `slide-in-from-left/right` and `slide-out-to-left/right`: shadcn keys them off Radix's physical `data-[side=…]`.
- Design at **360px first**; add `sm:`/`md:`/`lg:` only to enlarge. Never design desktop first and squeeze.
- A grid without `grid-cols-*` on phones sizes its column to the widest child: a table inside overflows the page. Give such grids `grid-cols-1` and their flex children `min-w-0`. `tests/e2e/dashboard.spec.ts` checks every dashboard screen for horizontal scroll on both projects.
- Touch targets ≥ 44px (`h-11` for primary buttons and inputs on the storefront).
- The primary mobile action (add to cart, checkout, save) sits in a sticky bottom bar on phones.
- Latin/number runs inside Arabic text: phones, emails, SKU codes and order numbers are wrapped in `<bdi>` or rendered with `dir="ltr"` (inputs for phone/email/password use `dir="ltr"` + `text-start`).
- Icons that point a direction (chevrons, arrows, "back") get `rtl:rotate-180` or use the logical icon.
- Digits are Western (`150.00`, D39); currency suffix `ج.م`.
- Check every screen at 360px and 1280px before calling it done; e2e runs on both projects.

## 4. Data and auth

- **Same origin only.** The browser calls `/api/*` and `/sanctum/*` on the tenant host. Laravel resolves the tenant from `Host` only, so whatever forwards these paths must keep the browser's `Host`:
  - dev / bare `next start`: the catch-all route handlers `app/api/[...path]` and `app/sanctum/[...path]` call `lib/server/backend-proxy.ts`, which forwards to `BACKEND_HOST:BACKEND_PORT` (default `127.0.0.1:8000`) with the original `Host`, cookies, `Origin` and `Referer`. Next's `rewrites()` cannot be used: its external proxy replaces `Host` with the destination host. Route handlers get `(request, context)`: pass only the request on.
  - production: Nginx sends both paths to PHP-FPM before they reach Next, with `Host` preserved (tasks/11).
- Never send `tenant_id`; never pick the tenant on the client; never compute a final price on the client.
- `lib/api/client.ts` is the only place that calls `fetch`. It:
  - sends `credentials: 'include'`, `Accept: application/json`, `X-Requested-With: XMLHttpRequest`, and `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie;
  - fetches `/sanctum/csrf-cookie` once before the first mutating request when the cookie is missing;
  - unwraps `{ data }`, returns `undefined` for `204`;
  - throws `ApiError` (`status`, `code`, `message`, `details`, `items`) built from the error envelope;
  - `419` → refreshes the CSRF cookie and retries **once**;
  - `401` on a protected call → `onUnauthenticated(surface)` (redirect to `/dashboard/login` or `/account/login` with `?next=`);
  - `503 store_unavailable` → `StoreUnavailableError`, rendered as the full-page «المتجر غير متاح».
- Session hooks: `useDashboardSession()` / `useCustomerSession()` return the user or `null` (a 401 from `me` is "logged out", not an error).
- Show `messageFor(error)` from `lib/copy/ar.ts`. It shows the envelope message, which is already Arabic, specific and safe. It falls back to the code's message in `ar.errors` when there is no envelope, and for the generic `server_error` / `http_error`. `ar.errors` is a `Record` over every `ErrorCode` in the spec, so a new backend code is a type error until it gets Arabic text.
- Query keys only from `lib/api/keys.ts`. Mutations invalidate exactly the keys they change. A mutation that returns the new state (the cart, a cancelled order) writes it with `setQueryData` and invalidates only the lists.
- Server components may read storefront data only through `lib/server/store-data.ts`, which goes through `proxyToBackend` with the shopper's Host, cookies and a Referer (so Sanctum sees the session and prices follow D1). Production: `BACKEND_HOST/PORT` must reach Laravel (Nginx/PHP-FPM) from the Next server. Any failure falls back to loading in the browser.
- Images are same-origin `/storage/...` (D61), optimised by `next/image` (`images.localPatterns`); `app/storage` proxies them in dev.
- Dev and LAN stores run on **http**, which is not a secure context: no `crypto.randomUUID()` (use `crypto.getRandomValues`), no `navigator.clipboard` (fall back), as the checkout key and the price-list share button do.

## 5. Code style

- Components: PascalCase file and export (`DashboardLoginForm.tsx`), named exports. Default exports only where Next.js requires them (`page`, `layout`, `error`, `not-found`).
- Hooks: `useX`, one concern each. Server components by default; `'use client'` only for interactivity, as low in the tree as possible.
- No `any`; no non-null `!` except on values the type system cannot see (comment why). Types for API data come from `lib/api/types.ts` aliases of the generated schema.
- No inline Arabic strings in components; no `console.log`.
- Class names: `cn()` from `@/lib/utils` for conditionals; brand colours only through theme tokens (`bg-primary`, `text-primary-foreground`), which `applyBranding()` drives from tenant settings.

## 6. Testing standard

"Done" = every behaviour added has a test that fails without the code.

| Code                         | Test                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `lib/**` module              | Vitest unit test, every branch (client: unwrap, errors, 401/419/503, CSRF bootstrap)    |
| Component/page with logic    | Testing Library: renders in RTL, validation messages, server error display, success path |
| New error code in the spec   | `ar.ts` has a message (enforced by `Record<ErrorCode, string>` + a test)                |
| User flow                    | Playwright spec on both `mobile` and `desktop` projects                                 |

- Test names are sentences, like the backend: `it('retries once after a 419')`.
- Stub `fetch` per test; never hit the network in Vitest.
- `npm run typecheck && npm run lint && npm test` must be green, plus `npm run build` for anything touching routing/config.
- E2E (`npm run test:e2e`) runs against `php artisan serve` + `next dev`, started by Playwright if they are not running. Chromium maps `*.gomal.test` to 127.0.0.1 itself (`--host-resolver-rules`), so no hosts entry is needed. It is a manual gate until CI exists.
  - The backend must be seeded (`php artisan migrate:fresh --seed`: the alnoor tenant + StorefrontDemoSeeder catalog).
  - `workers: 1`: `php artisan serve` answers one request at a time, parallel workers starve it into timeouts.
  - Calls a test makes itself go through the page (`page.evaluate(fetch)`), not `page.request`: Node does not get Chromium's host mapping. OTPs come from `GET /api/_test/last-otp` (D62); each run registers a new phone (5 OTPs per phone per hour).
  - Shared helpers live in `tests/e2e/helpers.ts`: `api()` (a CSRF-aware JSON call from the page), `loginAsOwner()`, `placeShopperOrder()` (a shopper in their own browser context registers and checks out through the store API). Specs that change data scope it to names made in the run, so the seeded catalog other specs rely on stays as is.
- jsdom gaps are filled in `tests/unit/setup.ts` (ResizeObserver for Radix, elementFromPoint for input-otp), assigned rather than `vi.stubGlobal` because `unstubGlobals` resets stubs after each test. `userEvent.setup()` installs its own `navigator.clipboard`: use `fireEvent` when a test stubs the clipboard.
- Tests that run Node-only code (the proxy) start with `// @vitest-environment node`.
- Inside `<main>`, query alerts as `getByRole('main').getByRole('alert')`: Next adds its own `role="alert"` route announcer to every page.

## 7. Never

- Never call `fetch` outside `lib/api/client.ts`, or a backend URL other than relative `/api/...`.
- Never hand-edit `lib/api/schema.d.ts`; regenerate it.
- Never use physical direction classes or `dir="ltr"` on layout containers.
- Never store auth tokens in `localStorage`; the session is the httpOnly cookie.
- Never hard-code Arabic copy, colours, or the tenant name in components.
