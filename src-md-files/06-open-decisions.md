(e) `on_hand` is the opening stock of a new product; for an existing one it is an `adjustment` with the reason «استيراد» (no-op when equal, D35; below reserved is a row error, BR-INV08). A status change follows BR-P04. (f) The preview dry-runs the real import inside a rolled-back transaction, keeps the file 24 h under its token and returns the first 200 errors; a token imports once. (g) One audit batch per import: `catalog.import_started` by the user, the queued job's records by `system` (it has no session; the run keeps `created_by`, movements carry the user), closed by `catalog.imported` / `catalog.import_failed`; inside a batch an update that changes no product field writes no `product.updated`. (h) More than 5,000 products (`catalog.export_sync_limit`) export through a job; the file waits 24 h behind a signed link (`409 export_not_ready` until written). (i) The import job applies 200 rows (`catalog.import_chunk`) and queues itself for the rest, so no job outlives the queue's 90 s retry window; it is tried once, so a crash ends the run `failed` with the rows applied so far kept. | BR-P12, BR-P13, BR-PR10, BR-INV08 |
| D88 | Pre-orders (V2 Task 10)                                    | (a) A pre-order is an order of `kind = preorder`: status `pending`, its lines `reserved = false` (no stock held, BR-INV01 stays true), prices indicative at today's tiers and set again on conversion. The merchant may still edit its delivery address. (b) Only a `coming_soon` product with `preorder_enabled` is pre-ordered (`cart_line_invalid` / `checkout_failed` `preorder_unavailable`). (c) Confirming checks the MOQ and the credit limit; the minimum order value does not apply. Open pre-orders count in the credit exposure at their remaining indicative total (D77). The merchant gets a `new_preorder` bell. (d) The cart keeps pre-order lines apart (`cart_items.kind`); checkout takes only the order lines and `POST /store/checkout/preorder` only the pre-order lines. A pre-order line whose product stops taking pre-orders (went active or inactive, or pre-orders turned off) is dropped at the next cart load as `preorder_closed`. (e) Conversion is an explicit merchant action (`orders.manage`) once the product is `active` (`409 product_not_active` before); going active only reports the demand (`meta.preorder_demand`). (f) The rest stays on the pre-order (`converted_quantity`, a `converted` line change, totals on what is left); a pre-order with nothing left is closed (`converted_at`, state `converted`, status stays `pending`) and can no longer be cancelled. | D89 | Customer prices (V2 Task 11)                               | (a) **Precedence (BR-PR14):** a price negotiated with the customer for the SKU always applies, at every quantity, even above the normal price (it is what was negotiated). Groups give one % off the **base** price, not their own tiers; a tier below the group price still wins. (b) The group % is 0–90 (0 = a level without a discount), the group price is rounded half-up to the piaster (D27) and never below 0.01. (c) A customer is in at most one group. Group names are unique in the store (`409 duplicate_name`). | D90 | Promotions (V2 Task 12)                                    | (a) **Precedence (BR-PR15):** a price negotiated with the customer (D89) still wins outright and is never undercut by a promotion. Promotions do not stack: a SKU in several live promotions takes the one with the highest %, the oldest on a tie. (b) A promotion is one % off the **base** price, more than 0 and below 90; the promotion price is rounded half-up to the piaster (D27) and never below 0.01. A tier below it still wins at its quantity. (c) A promotion is live while its status is `scheduled` or `active` and `starts_at ≤ now < ends_at`, judged at the moment of pricing: the cart, the storefront and checkout (re-checked inside the checkout transaction, BR-PR06) all read the clock, so an offer that ended between cart and checkout is not applied. `pricing:promotions-tick` (every minute) moves the stored status scheduled → active → ended for the dashboard; no price is cached, so nothing else needs bumping.
